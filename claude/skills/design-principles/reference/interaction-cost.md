# Interaction-cost refinements

Load this reference when the target contains a multi-step task, hidden choices, repeated entry, or form-input friction. Review at most one or two tasks.

## I1. Map cost across the task path

Source basis: supplied textbook, physical pp. 98–99, 101–109, and 116–119. Impeccable already covers cognitive load; this rule consolidates mental, physical, and time costs in one task map.

For each required step, record only what helps a decision:

- immediate user goal and the control or content used;
- mental work: search, comparison, interpretation, remembering, or context switching;
- physical work: taps, typing, pointer travel, scrolling, or repeated entry;
- time work: route changes, network waits, loading, or recovery;
- protective purpose: review, consent, trust, privacy, security, or error prevention.

| Part | Guidance |
|---|---|
| Trigger or symptom | A task repeats entry or navigation, loses context, hides comparison, or adds unexplained waits. |
| Action | Remove, combine, or move only avoidable cost. Preserve control, comprehension, recovery, and known-value correction. |
| Do not use | Do not impose a three-click rule, step ceiling, or four-choice limit. Do not count all clicks as equal. A fifth legitimate choice is not a defect by count alone. |
| Verify | Walk the same task before and after with representative content. Compare remembered facts, context switches, repeated entry, action count, waits, errors, and protective steps without inventing user outcomes. |

## I2. Choose direct controls or menus by use

Source basis: supplied textbook, physical pp. 100–108 and 111–113, refined to avoid fixed choice ceilings.

| Part | Guidance |
|---|---|
| Trigger or symptom | A frequent choice is hidden behind recall-heavy navigation, or a long or changing set consumes the surface. |
| Action | Show a choice directly near the object it changes when use is frequent, the set is stable, and comparison matters. Use a menu, search, or progressive disclosure when the set is long, dynamic, uncommon, or needs staged explanation. Show representative content before a promotional gateway when that content is the value. |
| Do not use | Do not expose every option by default, move global actions next to every object, replace labels with icons or color, or make meaning hover-only. |
| Verify | Test discovery time, comparison, keyboard order, touch targets, narrow layout, localization, and change handling. Confirm direct controls and menus preserve the same meaning and state. |

## I3. Fit inputs to expected data

Source basis: supplied textbook, physical pp. 114–119. Server authority, accessibility, and segmented-code behavior are operational synthesis.

| Part | Guidance |
|---|---|
| Trigger or symptom | A field summons the wrong keyboard, blocks paste or autofill, repeats known data, fragments one value, or makes correction costly. |
| Action | Check persistent label, constraints, semantic `type`, `inputmode`, `autocomplete`, locale, expected length, paste, password manager, autofill, correction, preserved input, and inline errors. Keep server validation authoritative. Use one logical code input when a segmented visual would add awkward stops, unless a multi-input design proves equivalent behavior. |
| Do not use | Do not infer valid data from visual field width, block paste by default, trust client validation alone, validate noisily on every keystroke, or remove confirmation when it prevents a costly error. |
| Verify | Exercise keyboard, screen reader, mobile keyboard, paste, autofill, backspace, selection, invalid input, server rejection, retry, localization, and focus recovery. Confirm values survive recoverable failure. |

## I4. Keep protective friction

Source basis: supplied textbook, physical pp. 105–109, 120–122, and 134–135, refined against one-click and fixed destructive-dialog recipes.

| Part | Guidance |
|---|---|
| Trigger or symptom | A proposal removes review, consent, confirmation, re-authentication, or a safe exit only to shorten the path. |
| Action | Keep or add friction when it protects destructive, irreversible, financial, private, or security-sensitive work. Prefer undo when it is genuinely safe. Follow platform order, focus, and reach conventions. |
| Do not use | Do not encode danger through red or button position alone, force confirmation for harmless reversible actions, or demand bottom navigation from a thumb-zone diagram. |
| Verify | Check consequence naming, explicit consent, cancel or undo, focus placement and return, keyboard and touch paths, repeated activation, recovery, audit needs, and practical phone reach for frequent actions. |

## Impeccable tension

Impeccable critique currently treats groups and visible options above four as checklist failures and converts failed items into a severity score. When formal critique is explicitly requested, keep its report but identify that threshold as a heuristic. Compare simultaneous mental work, set stability, frequency, and task evidence before recommending grouping or disclosure.
